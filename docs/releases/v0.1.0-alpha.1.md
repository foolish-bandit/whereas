# Whereas v0.1.0-alpha.1

Whereas now closes the gap between identifying a playbook deviation and getting the right human work underway.

## Headline feature: findings become traceable work

Each persisted failed playbook finding now offers a **Plan remediation** action. The plan is loaded only when opened and answers four questions directly:

1. What approved language is available?
2. Where did it come from?
3. Why was that source selected?
4. Is remediation work already in the Inbox?

Whereas does not generate a clause, silently alter the Repository record, or present AI-written language as firm-approved language.

## Deterministic approved-language policy

Whereas uses the following source order:

1. Firm-authored preferred language persisted with the playbook rule.
2. An active Clause Manager source with the same normalized clause type.
3. No language, with a clear instruction to add an approved source.

Clause Manager candidates are ranked deterministically by:

1. `preferred` tag;
2. `default` tag;
3. broad scope;
4. most recent update;
5. stable UUID tie-break.

Jurisdiction- or record-type-specific language remains visible, but the reviewer receives an explicit scope warning before using it.

## One durable Inbox task per finding

A new tenant-scoped `finding_remediation_tasks` link table ties one persisted finding to one Inbox task and stores source identifiers without copying legal text.

The workflow is idempotent:

- first action creates the task;
- repeated actions return the existing task;
- a dismissed task is reopened rather than duplicated;
- a completed task remains the durable record of the work;
- a database uniqueness constraint is the concurrency backstop.

The generic Inbox API cannot forge remediation work or alter its provenance and Repository linkage.

## Review tab cleanup

The Review tab previously contained both persisted backend playbook results and a separate client-only deterministic checklist. That could produce duplicate or contradictory findings.

The client-only checklist is gone. Persisted playbook runs are now the single review source of truth, while exact evidence highlighting and reviewer status controls remain intact.

## Frontend experience

The new remediation card:

- fetches only when expanded;
- aborts stale requests;
- presents source provenance before language;
- lets the reviewer copy approved language explicitly;
- creates or reopens Inbox work;
- deep-links to the Inbox task;
- keeps task creation available when no approved language exists;
- states plainly that Whereas will not edit the Repository record automatically.

Demo mode follows the same source precedence and reuses one session task per finding without implying that any clause was generated by AI.

## Security and auditability

- Every finding, source, task, assignee, and link query is scoped to the active organization.
- The new link table uses direct-organization PostgreSQL Row-Level Security.
- Audit events record creation and reopening using identifiers only.
- Approved language, exact evidence, guidance, source display names, counterparty data, storage keys, wrapped keys, and document bytes are excluded from audit details, link rows, and task metadata.
- Concurrent create requests use a nested transaction so the losing request cannot leave an orphan Inbox item.

## Research foundations

The workflow incorporates proven ideas from mature open-source systems:

- OpenContracts-style evidence and annotation provenance;
- DefectDojo-style finding lifecycle and deduplication;
- GitHub code-scanning alert-to-work-item traceability;
- Paperless-ngx deterministic workflow routing;
- n8n and Activepieces human-in-the-loop transitions;
- Documenso and Cicero separation between approved templates and execution.

The detailed source review is in `docs/research/2026-08-04-review-to-action-open-source.md`.

## Upgrade notes

1. Back up the database.
2. Upgrade the application code.
3. Run `alembic upgrade head` from `backend/`.
4. Confirm the `finding_remediation_tasks` table has Row-Level Security enabled and forced.
5. Run the complete backend and frontend verification gates before production use.

This is an alpha release intended for evaluation and testing. Review approved language and scope warnings carefully before applying anything to a legal document.
